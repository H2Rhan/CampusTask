# 产品路线图 —— CampusTask · 邻行

> 更新日期：2026-09-16
> 目标：先把南开大学津南校区做成一个**真实可用**的校园互助应用，再谈扩张。

## 版本规划

### ✅ v0.1（当前，已发布）

任务撮合全流程闭环：

- 学号注册登录、校园信用档案
- AI 一句话发布（LLM + 离线规则引擎双保险）
- 边际成本智能匹配（为任务找人 / 任务找我）
- 校园数字地图（津南 22 节点 43 边，Dijkstra + A*）
- 任务状态机（9 主状态 + 仲裁分支，服务端强校验）
- WebSocket 任务聊天室（快捷操作驱动状态机）
- 虚拟钱包（冻结 → 结算 → 仲裁退回，流水可审计）
- 仲裁系统（证据时间线 + 规则引擎建议 + 管理员裁决）
- 匈牙利算法批量调度、运营数据看板
- 35 项自动化测试

### 🚧 v0.2 —— 真实化（下一步）

| 事项 | 说明 | 验收标准 |
|---|---|---|
| 地图实地测绘 | 两轮车 + GPS 轨迹校准坐标，地点扩至 60+（全部宿舍斋、快递点、校门、食堂、教学楼） | 任意两点距离误差 < 15% |
| 微信一键登录 | 申请小程序 AppID，code2session 正式通道 | 新用户 10 秒内完成注册 |
| 订阅消息 | 接单提醒 / 取件提醒 / 送达提醒 / 验收提醒 | 全链路通知可达 |
| UI 打磨 | 首页任务卡片、地图可视化、发布引导 | 核心流程 ≤ 3 步 |

### 📋 v0.3 —— 内测上线

- 津南校区小范围内测（3 个宿舍楼 + 计算机学院群）→ 扩大至 100–200 人
- 多任务顺路打包：一趟多单（CVRP 扩展，边际成本仍最优）
- 运营看板可视化（注册/接单率/完成率/复购率 图表）
- 基于真实数据的动态悬赏建议（目前为静态费率表）

### 🔭 v1.0 —— 正式运营

- 真实支付（微信支付分账，平台不沉淀资金）
- 位置实时共享（接单者轨迹对发布者可见，任务结束即关闭）
- 多校区支持（八里台校区图、校区间任务隔离）
- 反作弊：同人自接自、刷分识别

## 技术债与已知限制

- 校园地图坐标为 v0.1 示意值 → v0.2 测绘校准前不做精确 ETA 承诺
- Redis 目前仅作配置预留，在线状态/限流待接入
- 管理员名单为硬编码学号 → 正式版改角色表
- 信用规则为 v1 静态规则 → 内测后根据数据调参

## 运营指标（内测期间每周看）

注册人数、日活、发布任务数、接单率、完成率、平均完成时长、
平均悬赏、复购率、仲裁率、用户满意度（NPS）。

> `GET /api/v1/stats/overview` 已实现全部指标的实时统计。
