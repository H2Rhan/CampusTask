# 产品需求文档（PRD）——「邻行」CampusTask 校园智能互助任务平台

> 版本：v0.1（MVP） · 更新日期：2026-09-16

---

## 1. 产品定位

**「邻行」不是校园跑腿平台，而是一个基于校园数字地图和 AI 智能匹配的学生闲置运力共享平台**：让用户在日常出行过程中顺路完成他人的小任务，以更低成本实现校园互助。

核心理念：**让每一个经过某个地方的人，都可能成为一次"顺路服务者"。**

四个转变：

| 从 | 到 |
|---|---|
| 人找任务 | **任务找人** |
| 最短路径 | **最低边际成本** |
| 陌生交易 | **校园可信交易** |
| 单次跑腿 | **校园互助生态** |

### 与传统跑腿（美团跑腿等）的区别

| 维度 | 传统跑腿 | 邻行 |
|---|---|---|
| 服务者 | 专业骑手 | 校园普通用户 |
| 接单方式 | 平台派单 / 抢单 | 系统按顺路程度推荐，用户自由选择 |
| 核心逻辑 | 配送 | **顺路互助** |
| 服务费 | 相对较高 | 低额悬赏 + 极低撮合服务费 |
| 地图 | 通用导航 | **校园专属数字地图** |
| 匹配依据 | 距离为主 | 路线 + 时间 + 信用 + 收益 |
| 用户关系 | 陌生服务 | 校园实名身份体系 |
| 信用 | 骑手/商家体系 | 校园信用分生态 |
| 仲裁 | 平台客服 | 任务证据链仲裁（规则引擎 + 人工） |
| AI | 通常不是核心 | **AI 任务理解 + 智能匹配** |

## 2. 目标用户与场景

**首期封闭场景：南开大学津南校区**（地图规模可控、用户集中、任务类型明确）。

典型场景：

> 学生 A："帮我从津南校区西门菜鸟驿站取一个快递送到中海国际宿舍，愿意支付 5 元。"
> 系统发现学生 B 的日常路线为 中海国际 → 西门 → 学一食堂，与任务高度重合，遂把任务推荐给 B。
> B 接单顺路完成，A 验收，系统自动结算。

## 3. 功能需求（六大模块）

### 3.1 用户系统

- 学号 + 密码注册登录；姓名 / 学院 / 年级 / 手机 / 宿舍区域
- 校园身份认证（MVP 默认通过；正式版接入学校统一身份认证 + 微信 OpenID 绑定）
- 公开信用档案：信用分、完成次数、守信率、好评率、平均完成时长

### 3.2 任务发布系统

- **AI 一句话发布**（核心体验）：自然语言 → 结构化任务
  - 输入：`帮我下午五点去西门菜鸟驿站拿快递送到中海，给5块`
  - 输出：`{task_type: 快递取送, start: 西门菜鸟驿站, destination: 中海国际, deadline: 17:00, reward: 5}`
  - 双引擎：LLM（OpenAI 兼容 API）+ 离线规则引擎兜底
- 手动表单兜底：任务类型（8 类）、标题、描述、起点、终点、最晚完成时间、悬赏、特殊要求
- 自动补全：预计距离、预计时间、建议悬赏

### 3.3 智能任务匹配（核心算法）

- 平台主动寻找"完成任务时增加的额外成本最低的人"
- **边际成本**：`MC = Cost(原路线 + 任务) − Cost(原路线)`，支持取件→送达有序插入（Best Insertion）
- **匹配评分**：`Score = w₁·D_route + w₂·T_delay + w₃·C_credit + w₄·R_reward`，归一化为 0–100 顺路匹配度
- 输入：用户登记的"我的日常路线"（如 宿舍 → 食堂 → 图书馆）

### 3.4 校园数字地图

- 南开大学津南校区 Node/Edge 道路图（22 节点 / 43 边，v0.1 示意坐标，待实地测绘校准）
- Dijkstra 最短路径 + A*（欧氏启发式）
- 地点别名解析（"西门那个快递站" → 西门菜鸟驿站）

### 3.5 任务执行与实时沟通

- 撮合成功才建立聊天室；任务结束自动归档（降低隐私风险）
- WebSocket 实时聊天 + 快捷操作按钮：
  - 📍 到达取件点 / 📦 已取到物品 / 🚚 前往目的地 / ✅ 已送达
  - 快捷操作直接驱动任务状态机

### 3.6 可信交易与仲裁

- **虚拟钱包**（当前版本）：发布冻结悬赏 → 验收自动结算 → 仲裁冻结待裁
- 合规说明：正式上线不自建资金池，接入微信支付等持牌机构
- **仲裁**：规则引擎自动生成证据时间线与裁决建议 → 管理员人工裁决 → 资金处理 + 信用奖惩
- **信用体系**：完成 +1 / 好评 +0.5 / 差评 −3 / 弃单 −5 / 仲裁败诉 −10；信用 < 60 限制高价值任务

## 4. 任务状态机

```
待接单 → 已接单 → 进行中 → 已到达取件点 → 已取件 → 配送中 → 待验收 → 已完成 → 自动结算
                    └────────── 申请仲裁 → 平台介入 → 证据审核 → 裁决 → 资金处理 ──────────┘
```

所有状态迁移由服务端状态机校验，非法跳转一律拒绝。

## 5. 四大核心亮点

1. **校园低成本互助经济**：把学生的闲置时间 + 日常出行路线转化为可交易的校园闲置运力
2. **基于边际成本的智能任务匹配**：不是谁最近，而是谁"顺路"（可独立包装为数学建模作品）
3. **校园数字地图 + AI 任务理解**：自然语言 → 结构化 → 地点识别 → 路径规划 → 接单推荐 全链路
4. **任务可信交易闭环**：身份认证 → 发布 → 资金冻结 → 执行 → 证据记录 → 验收 → 结算 → 信用 → 仲裁

## 6. 非功能需求

- 性能：匹配引擎单次计算 < 50ms（22 节点图实测毫秒级）
- 安全：PBKDF2 密码哈希、JWT 鉴权、接口级权限校验（发布者/接单者/管理员）
- 合规：不托管真实资金；位置数据最小化采集，仅用于任务履约

## 7. MVP 边界（第一版不做什么）

- 不做"校园版美团"大而全；不做商家入驻
- 不做 AI 自动仲裁（规则引擎 + 人工）
- 不做真实支付（虚拟钱包演示）
- 不做跨校区/跨学校
